# TITAN Reader — Dictionary & Vocabulary (Phase 3)

Phase 3 adds a fully offline dictionary, recent lookups and a personal
vocabulary ("My Vocabulary") on top of the Phase 2 selection pipeline.
Everything here is **source-backed**: no definition, example, synonym or
antonym is ever generated by AI or fabricated by the app.

## Dictionary source investigation (§2–3)

Candidates reviewed before implementation:

| Source | License | Verdict |
| ------ | ------- | ------- |
| **WordNet Release 3.0** (Princeton) | Permissive: free to use, copy, modify and distribute for any purpose without fee, provided the copyright notice appears on all copies | ✅ **Selected** |
| Wiktionary dumps | CC BY-SA (attribution + share-alike, large/irregular dumps) | Rejected: share-alike burden, poor fit for offline shards |
| dictionaryapi.dev | Free remote API, no redistribution rights | Only as **optional online fallback**, never bundled |
| GCIDE / Webster 1913 | Public domain but stale language, inconsistent markup | Rejected |

**Decision**: bundle WordNet 3.0 (147,306 words) as gzipped JSON asset
shards, with dictionaryapi.dev as an optional, **off-by-default** remote
fallback. WordNet provides definitions, usage examples, synonyms, antonyms
and part-of-speech grouping. It provides **no phonetics**, so the panel
never displays fake pronunciation (see "Honest gaps" below).

### License & attribution (required by the license)

> WordNet 3.0 Copyright 2006 by Princeton University. All rights reserved.

- Full license text ships in `assets/dictionary/manifest.json`.
- The attribution string is rendered inside every dictionary entry
  (`dictionary-attribution`) and returned by
  `BundledDictionaryDataSource.attribution`.
- Build pipeline: `project_titan/tools/build_wordnet_dictionary.py`
  (regenerates the dataset from the official release).

## Dataset layout

```
apps/titan_reader/assets/dictionary/
├── manifest.json        # source metadata, license, attribution, shard index
├── headwords.json.gz    # sorted headword list (existence checks + prefixes)
└── shards/<key>.json.gz # entries grouped by two-letter shard key (553 shards)
```

- Shard key = first two letters when both are alphabetic, else `_` + first
  character. Total size ≈ 9 MB compressed.
- Shards are loaded lazily and cached with an LRU policy (max 12 decoded
  shards) — the whole dictionary never sits in memory (§39).
- `flutter:` assets in `pubspec.yaml` list **both** `assets/dictionary/`
  and `assets/dictionary/shards/` (directory entries are not recursive).

## Lookup pipeline (local-first)

```
raw selection/query
   ↓ WordNormalizer.normalizeWord   ("Ephemeral," → ephemeral)
DictionaryService.lookup
   ↓ 1. bundled local source        (BundledDictionaryDataSource)
   ↓ 2. dictionary cache            (titan.reader.dictionary.cache)
   ↓ 3. remote source               ONLY if remoteLookupEnabled == true
   ↓ 4. record recent lookup
result: Found / NotFound(offline: true|false) / Failure(typed error)
```

- `DictionaryLookupResult` is a sealed type; the UI renders explicit states
  for loading, success, not-found, offline-unavailable and typed failures —
  raw HTTP errors never reach the user (§16–18).
- Multi-word selections are rejected before lookup (§14): the reader shows
  a guidance snackbar and never opens the panel for phrases.

## Privacy: LOCAL_ONLY by default (§34)

- `remoteLookupEnabledProvider` defaults to **false**. No word ever leaves
  the device unless the user flips the "Online lookup" switch shown inside
  the offline-unavailable state.
- When enabled, only the normalized word itself is transmitted
  (GET to `api.dictionaryapi.dev`); no document, page, selection or
  user identity is ever sent.
- Cached remote entries store provenance (`sourceId`) alongside the data.
- Dictionary/vocabulary stay fully separate from QuizForge AI and from any
  AI feature. Grammar remains a placeholder (§35) — designed for, but not
  implemented in, Phase 3.

## Storage namespaces

| Namespace | Key(s) | Content |
| --------- | ------ | ------- |
| `titan.reader.dictionary.cache` | `dictionary:<normalizedWord>`, `index` | Remote lookup cache with provenance |
| `titan.reader.dictionary.recent` | `lookups` | Recent lookups (word + timestamp, capped) |
| `titan.reader.vocabulary` | `all` | My Vocabulary words |

All persisted through the shared `titan_storage` `StorageService` port
(`InMemoryStorageService` in tests). Vocabulary is separate from QuizForge
data and survives document deletion (§23–30).

## Recent lookups

Recorded automatically on every completed lookup (deduplicated, most recent
first, capped). Shown on the panel's search home with tap-to-reopen and a
clear-history action. They are Reader data, not shared with QuizForge.

## My Vocabulary

`VocabularyWord` captures:

- the word (raw + normalized) and dictionary source id;
- **source context**: document id/name, page and selected text —
  "jump back to source" navigates to `/reader/:documentId?page=N`;
- **personal meaning / personal note**: user-owned text that never
  overwrites or mixes with source-backed definitions;
- mastery status `New / Learning / Known / Mastered` — initial `New`,
  changed **only manually**; no spaced repetition (§27).

Saving the same normalized word twice is a no-op returning the existing
entry. All mutations persist immediately and survive restarts.

## Entry points

- Selection toolbar: **Dictionary** (opens panel with the word) and
  **Save Word** (saves directly with source context).
- Reader AppBar: dictionary button opens the search/recent-lookups view.
- Library AppBar: vocabulary button opens `/vocabulary`.
- Vocabulary tile: tap opens the dictionary entry; open-source button jumps
  to the recorded page.

## Honest gaps (limitations)

- **No pronunciation**: WordNet ships no phonetics; the panel shows IPA /
  audio only if a future source provides them — never faked (§8).
- **No word origin**: shown only if the source provides it (WordNet does
  not).
- Grammar stays a placeholder by design (§35).
- Remote fallback is best-effort; offline behavior is the primary contract.
